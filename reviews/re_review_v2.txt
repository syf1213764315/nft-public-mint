## NEW Findings

### ð´ CRITICAL â `validate_chain` failure path treats wrong-chain RPC as transport error and fails over
**Location:** `RPCPool.call()` L256â276 vs `RPCClient.call()` L142.

`validate()` raises `SafeMintError` on chain mismatch (L218). The error message starts with `"chain X, expected Y"` â does **not** match `"RPC transport error"` or `"RPC 429"` or `"-32601"`. So it correctly propagates. â â but `watch` calls `primary.call("eth_call", â¦)` first and *then* checks chain via the later `validate_chain(fire, int(chain_hex, 16))` (L806). If the primary RPC silently lies about chainId for `eth_call` (some DRPC endpoints do), `eth_call` may execute against a different chain view. Recommend: `validate_chain(pool.best_client(), chain_id)` **before** the watch loop, not after.

### ð´ CRITICAL â Final `eth_call` simulation at L800 uses `max_retries=0` semanticsâ¦ wait, no, it uses default retries (6 Ã 11s = 66s) right before signing
**Location:** L800â803.

```python

gas_hex = fire.call("eth_estimateGas", [...])      # default max_retries=6
```

The hot-loop 429 fix only protects the **watch poll** (L793). The two pre-sign calls and the `eth_getTransactionReceipt` retry loop (L825â833, also `max_retries=1` â) use defaults. Under NodeFlare 1 req/10s, the final pre-sign simulation can stall 66s right at the trigger moment â missing the mint window. Same risk for `eth_estimateGas`. Recommend: `max_retries=1` on both final sim calls.

### ð  HIGH â `eth_gasPrice` against a free-mint tx has no fee cap; `enforce_limits` uses `gas_price_wei` as-is
**Location:** L581â588.

`gas_price_wei` comes from RPC with no ceiling. If the user sets `--max-fee 0.0005` but the chain tip is 50 gwei, the check `network_fee = gas_limit * gas_price_wei > max_network_fee_wei` does fire â good. But the comparison happens **after** `gas_limit = int(estimate * 1.15)` (L807). If estimate is 500k at 50 gwei â 0.025 ETH, check fails. Acceptable. **However**: there is no `max_fee_per_gas` ceiling independent of gas limit. A malicious/poisoned RPC returning `gasPrice=1000 gwei` causes the limit to fail loudly â fine. No bug here, downgrade to note.

### ð  HIGH â `parse_function_call` allows negative integers via `int(a, 0)` with no bounds check
**Location:** L517.

```python
elif t.startswith("uint"):
    words.append(f"{int(a, 0) & ((1 << 256) - 1):064x}")
```

`int("-1", 0) & ((1<<256)-1)` = `2^256 - 1` â silently coerced. For a `uint8` field this passes a garbage value that will revert on-chain (good) â but the user gets no pre-flight warning. Lower priority: most ABIs reject this at simulate time. **Not a critical bug**, but masks config errors.

### ð  HIGH â `broadcast_same_raw` "known transaction" returns keccak hash but the signed tx may have been nonce-shifted by a competing parallel broadcast
**Location:** L386.

If two wallets fire simultaneously and the second wallet's nonce collides with this wallet's pending tx on the mempool of endpoint A, endpoint B sees `already known` and returns the correct hash. But endpoint A returning a *different* hash (e.g. its own `eth_sendRawTransaction` accepting a different nonce) is not handled â the function returns whichever the loop hits first. **Pre-existing behavior, not introduced by the fix.** Note only.

### ð  HIGH â `keystore addr` and `keystore create` accept password from CLI without warning
**Location:** L905â922.

`resolve_password()` is called, but no warning is printed to stderr when `--password` is used (only the help text mentions env var). Recommend: print a one-line `[!] password passed on CLI â consider SAFE_MINT_PASSWORD env var` to stderr in these subcommands.

### ð¡ MEDIUM â `record_run` never writes FAILED/PENDING tx_hash updates when record_run was already called as BROADCAST

### ð¡ MEDIUM â `--mode auto` accepts `--max-price 0` (no per-NFT cap) silently

## Final Verdict: **NEEDS-FIX**

Two real pre-sign reliability bugs:
1. **CRITICAL**: `chain_id` not validated until *after* the watch loop completes â silent cross-chain view possible on misbehaving RPC.
2. **CRITICAL**: Final pre-sign `eth_call` + `eth_estimateGas` use default `max_retries=6` â under NodeFlare 1 req/10s, 66s stall right at trigger time, missing the mint window. The 429 fix was applied to the watch poll but not to the fire-time reads.
